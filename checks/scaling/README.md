# scaling: does a cost formula hold on every compiled instance?

A resource formula such as N = (10n − 6)r + 3n is a claim about what a compiler produces for every n and k. The
scaling tests compile the circuits on a grid of (n, k), count, and compare with the formula **exactly**. The grid
includes held-out points that were never used to find the formula, so a formula fitted to the training points
cannot pass by construction. Graphix runs here; compilers that need their own environment (Cabaliser) are read
from their records in `experiments/compilers/results/`.

A pass grants at most **empirical** on the grid: it is evidence, not proof. A Lean proof of the same formula is
what makes it hold for every n and k, and these tests then become the evidence for the assumptions that proof
names (gate counts, circuit width, no cancelling CZ). A failure gives the first count the formula misses. A
formula can be right asymptotically and still miss here, for example because of a constant term the grid
exposes. The verdict then reads "Does not pass scaling tests", not "false".

Shared code: `_compare.py` (the exact comparison and the evidence), `checks/_shared/grids.py` (the grids, the
cached counts, interpolation).
