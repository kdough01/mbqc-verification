# Reproducing Saadatmand et al. (arXiv:2406.06015v3): Table II

*Superconducting qubits in the millions: the potential and limitations of modularity* estimates the resources
for QFT and QSP Hamiltonian simulation on a modular superconducting FTQC architecture, compiled to graph states
(MBQC) with Rigetti's resource estimator (RRE) and Cabaliser. This folder re-runs Table II **with the authors' own
public pipeline**, settles the settings the paper does not state by calibrating on the rows whose circuits are
unambiguous, and records in the DAG what agrees, what does not, and what we found while checking.

The full record, with figures and every check's latest outcome, is the verification report:
[reports/saadatmand2024.html](https://kdough01.github.io/mbqc-verification/reports/saadatmand2024.html)
(generated by `dagtool report` from `dag/reports/saadatmand2024.yaml` and the DAG). The strategies that carry over
to other papers and the tools we use or may use are on
[reports/toolkit.html](https://kdough01.github.io/mbqc-verification/reports/toolkit.html).

## Protocol

1. **Reproduce.** Pin the code the paper used (RRE 0.26.33 at `9383b4d`, Cabaliser at its submodule commit,
   pyLIQTR 1.3.3 with qualtran 0.4.0), transcribe the configuration and Table II (printed text kept), run.
2. **Calibrate on the least ambiguous rows.** The QFT rows use `cirq.qft`: no random phases, no ancillas. Only the
   configuration can differ there, so a grid of real runs over the unstated settings (`calibrate.py`) settles it.
   The harder rows (Fermi–Hubbard, Ising) are then scored with those settings unchanged.
3. **Settle what each column counts** (`compare.MAPPING`), on the instances that pin each reading down.
4. **Re-derive** reported quantities from RRE's intermediate outputs with Appendix A's formulas (`rederive.py`).
5. **Test beyond the paper's tests:** compiled graphs on every basis input and random inputs (`cabaliser_inputs.py`).
6. **Check claims in the text** (random phases are conservative, `phases.py`).
7. **Measure** what the unstated settings do (`sensitivity.py`, `fh_widgets.py`) and how resources grow
   (`scaling.py`) — actual runs only, no fitting or extrapolation.
8. **Record.** Each quantity is a `reproduction` check on a DAG node (`dag/nodes/reproductions/saadatmand2024/`).
   Expected refutations carry an `acknowledged:` reason, so CI stays green while the finding stays visible.

## Running

```bash
bash experiments/rre/environment.sh            # once: builds .rre/ (git-ignored), runs RRE's own tests
source .rre/venv/bin/activate
bash experiments/rre/run.sh                    # calibration grid, Table II (small set), scaling, side studies
dagtool run --stale && dagtool check           # in the verifier's own environment
```

Needs Linux x86-64 with AVX2, gcc/make, git, [uv](https://docs.astral.sh/uv/) and Rust (installed from
conda-forge if missing). Each instance takes seconds; the whole small set takes a few minutes, most of it the
Cabaliser simulations (`CABALISER_SAMPLES` sets the number of random inputs, default 20). On GitHub, the
**reproduce** workflow (Actions → reproduce → Run workflow) does the same and commits the results.

## Calibration

`calibrate.py` runs QFT N-4, N-10 and N-25 at every combination of five settings (48 points, 144 runs) and scores
each against the 27 Table II columns of those rows. Exactly one point reproduces 26 of them; the runner-up gets 22.

| Setting | Settled value | First pass | Best score with any other value |
|---|---|---|---|
| failure budget (`target_p_algo`) | 0.05 (p_algo = 0.95 is a success probability) | 0.95 (Eq. 27 literally) | 15/27 |
| T-factory table | RRE's shipped table | Table I as printed | 22/27 |
| characteristic gate time t | 200 ns | 200 ns | 20/27 (50 ns) |
| widgets (QFT) | one widget per circuit | RRE example | 17/27 |
| logical-error fit | paper (κ 0.009, p_th 0.016) | paper | 15/27 (RRE's) |

The same runs settle the column readings (`compare.MAPPING`; the first pass's are `MAPPING_V1`): Table II's
ñ_logical is the input register (Parameter 15), not Appendix A's ñ (graph memory, Parameter 2); physical qubits are
modules × Parameter 14 (factories at their Q qubits), not the Parameter 35 RRE reports; T patches count all modules.
The settled configuration is `config_calibrated.yaml`; `reproduce_table2.py` adds the per-family settings.

## What reproduces (calibrated, within 1%)

| Instance | ñ | bus patches | T patches | phys. qubits | modules | runtime | power ×2 | energy |
|---|---|---|---|---|---|---|---|---|
| QFT N-4 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| QFT N-10 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| QFT N-25 | ✓ | 572 vs 2.02k | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| QFT N-100 (held out, 4 modules) | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| Fermi–Hubbard 2×2 | 38 vs 36 | 1.14× | 1.12× | 0.93× | ✓ | 0.21× | ✓ | 0.21× |
| Fermi–Hubbard 4×4 | ✓ | 1.67× | 0.94× | 1.13× | ✓ | 0.24× | ✓ | 0.24× |
| Ising 2×2 | 40 vs 67 | 0.69× | 0.98× | ✓ | ✓ | 9.3× | ✓ | 9.3× |

So 35 of 36 QFT numbers reproduce. With the configuration settled by QFT, what remains for Fermi–Hubbard and Ising
is in their circuits:

* **Fermi–Hubbard runtime follows widget granularity.** Runtime is mostly inter-module handover, paid per widget
  step (Eq. 21), and the paper does not say how it cut the circuit. At 4×4 the public widgetizer's levels give
  0.24×, 0.88×, 3.6× and 25× the paper's runtime (`fh_widgets.py`); the paper's lies between the 2,948- and
  11,572-step levels, and the finest level reproduces the paper's graph memory (83) exactly. At 2×2 any cut finer
  than the default fails in qualtran's adder decomposition (IndexError).
* **Ancilla allocation sets the register.** Reusing freed ancillas in allocation order (cirq's GreedyQubitManager,
  `maximize_reuse=False`) gives the paper's 74 at 4×4; fresh ancillas give 133, LIFO reuse 61. At 2×2 it gives 38
  against 36.
* **Ising 2×2** reproduces its physical qubits (0.4%) and T patches (2%) but not its register (40 vs 67) or runtime
  (9.3×); the circuit differs (lattice or encoding details); unresolved.
* **QFT N-25's bus patches** (2.02k printed) break the trend of their neighbours (88, 248, 2.02k, 3.39k against our
  88, 248, 572, 3,392); unresolved, consistent with a misprint.

## Other findings

* **Random phases are not conservative here.** §III.3 says random QSP phases give "a conservative overestimate".
  pyLIQTR 1.3.3's random mode uses one phase fewer for the sine sequence, so the circuit is slightly smaller:
  62,170 T against 63,575 with optimized phases at 2×2 (`results/phases.json`).
* **The Appendix C test cannot see wrong rotations.** Its reference table maps the rotation tag to T and uses
  Cabaliser's `Tdag = S @ T` (T³). From |000⟩ it passes; on random inputs it gives fidelity 0.013–0.24. With the
  real angle and a correct T†, the compiled graphs are right on every input. Worth reporting upstream.
* **Appendix A's two physical-qubit totals disagree** (Parameter 35 vs modules × Parameter 14); Table II uses the
  latter.
* **The other Appendix A formulas match RRE**, including the gate-synthesis T-count.

## Scaling (actual runs)

`scaling.py` runs QFT at N = 4…100 (14 sizes) and Fermi–Hubbard at N = 2…6 with the calibrated settings and writes
`results/calibrated/scaling.json`. Every point is a run; nothing is fitted or extrapolated; the paper's values are
shown only where Table II prints them. The QFT series crosses from two to four modules between N = 64 and 80.

## Trying another configuration (candidates)

A proposer who wants to try different settings does not edit this folder. It writes a candidate that picks one
declared value per setting (`settings_space.yaml`: failure budget, error fit, factory table, gate time, and per family
the widget level and ancilla allocation), runs it, and reads the verifier's feedback:

```bash
python experiments/rre/candidates.py validate candidate.yaml        # refused if anything is not declared
python experiments/rre/run_candidate.py --candidate candidate.yaml --out /tmp/cand   # RRE environment
dagtool feedback --node saadatmand2024.fh.4x4 --results-root /tmp/cand            # verifier environment
```

Feedback scores the candidate's results with the node's own checks; expected values must equal the frozen ones, so a
candidate cannot move the target. Adopting a configuration in the verifier (`config_calibrated.yaml`,
`reproduce_table2.py`) is a reviewed change, followed by a `reproduce` run.

## Larger instances (for the larger machine; not run here)

Fermi–Hubbard 8×8, 16×16, 20×20, QFT N-500 and N-1000, and Ising 5×5 have DAG nodes whose checks **skip** until
the results files exist. To run them with the calibrated settings:

```bash
git clone https://github.com/kdough01/mbqc-verification && cd mbqc-verification
git checkout -b rre-large
bash experiments/rre/environment.sh /scratch/rre          # any DIR; Linux x86-64 with AVX2
source /scratch/rre/venv/bin/activate
export RRE_COMMIT=9383b4d
/usr/bin/time -v bash experiments/rre/run.sh --only fh:8          # start here: note time and peak memory
/usr/bin/time -v bash experiments/rre/run.sh --only qft:500 ising:5
/usr/bin/time -v bash experiments/rre/run.sh --only fh:16 fh:20 qft:1000
git add experiments/rre/results/calibrated && git commit -m "RRE: larger Table II instances" && git push -u origin rre-large
```

Pushing runs the verifier, which picks up the new results files (they are listed under each node's `code:`), runs
the checks and commits the evidence. Run instances in separate processes so memory is released between them; the
`provenance` block of each result records the machine and the time taken. To extend the scaling series on that
machine: `python experiments/rre/scaling.py --fh 2 3 4 5 6 7 8 --qft 4 10 25 100 200 500`. Alternatively register
the machine as a GitHub self-hosted runner and start the **reproduce** workflow with `runner` set to its label and
`only` to the instance ids.

## Files

| File | What it does |
|---|---|
| `environment.sh`, `requirements-rre.txt` | pinned environment (RRE, Cabaliser, pyLIQTR 1.3.3, Python 3.11) |
| `config_paper_v3.yaml` | first pass: the configuration as printed |
| `config_calibrated.yaml` | the configuration the QFT rows single out |
| `paper_v3_table2.yaml` | Table II, all three families, as printed |
| `fh.py` | builds an instance (`--model fh|qft|ising`) and runs RRE; writes every output plus provenance |
| `compare.py` | maps RRE's outputs onto Table II's columns (`MAPPING`; `--v1` for the first pass's readings) |
| `calibrate.py` | the calibration grid on the QFT rows, with a ranked summary |
| `reproduce_table2.py` | every small Table II instance with the calibrated settings (`--only` for larger ones) |
| `scaling.py` | resources against problem size, actual runs only |
| `fh_widgets.py` | Fermi–Hubbard runtime at every widget granularity the public widgetizer produces |
| `rederive.py` | recomputes Appendix A parameters from RRE's intermediate outputs |
| `phases.py` | random vs optimized QSP phases |
| `cabaliser_inputs.py` | compiled graph states vs the circuit unitary on basis and random inputs |
| `sensitivity.py` | first pass: one unstated setting at a time |
| `settings_space.yaml`, `candidates.py` | the declared settings a candidate may choose from, and its validator |
| `run_candidate.py` | runs one candidate and writes results a node's checks can score |
| `run.sh` | runs all of the above |
| `results/` | first-pass results; `results/calibrated/` the calibrated ones. The DAG checks read both |
